# ADR-010: MPC Ceremony for Trusted Setup

**Status:** Accepted  
**Date:** 2026-02-17  
**Authors:** Alessandro La Gamba  
**Deciders:** Architecture team  

---

## Context

The Groth16 zero-knowledge proof system (ADR-013) requires a one-time **Trusted Setup** — a ceremony that generates the Common Reference String (CRS), consisting of the Proving Key (PK) and Verifying Key (VK). This setup involves computing powers of a secret scalar τ (the "toxic waste"):

```
CRS = { τ¹·G, τ²·G, ..., τⁿ·G } on BLS12-381
```

If any single party knows τ, they can forge arbitrary proofs — destroying the entire ZK system. The challenge: generate τ distributedly so that no single party (including 0xMeridian itself) ever knows the complete value.

Two approaches were evaluated:
- **Option A:** Single-party trusted setup (one party generates τ, destroys it)
- **Option B:** Multi-Party Computation (MPC) ceremony — n parties each contribute, toxic waste is secure if at least one party destroys their share

---

## Decision

**MPC Ceremony: n participants each contribute a secret scalar s_i. The combined τ = s_n × ... × s_1 is never known by any single party. Each participant generates a ZK-Proof of their own honest contribution.**

```
PARTICIPANT 1 (P1)
  Generate s_1 ∈ Fq (random scalar)
  Compute: contribution_1 = s_1 · G (generator point)
  Compute: proof_1 = ZK{ knows s_1 : contribution_1 = s_1·G }
  Transmit (contribution_1, proof_1) to P2
  DESTROY s_1 (hardware wipe, Secure Enclave)

PARTICIPANT 2 (P2)
  Receive (contribution_1, proof_1)
  Verify proof_1
  Generate s_2 ∈ Fq (random scalar, in Secure Enclave)
  Compute: contribution_2 = s_2 · contribution_1  (= s_2·s_1·G)
  Compute: proof_2 = ZK{ knows s_2 : contribution_2 = s_2·contribution_1 }
  Transmit (contribution_2, proof_2) to P3
  DESTROY s_2

... (repeat for all n participants)

FINAL OUTPUT
  PK = { τ^i · G : i = 1..n } where τ = s_n × ... × s_1
  VK = { τ · G₂, α · G₂, β · G₂, γ · G₂, δ · G₂ }
  Published to all nodes in the constellation
```

### Security Properties

| Property | Guarantee |
|----------|-----------|
| Soundness | τ is secure as long as ≥1 participant honestly destroys their s_i |
| Verifiability | Each participant's contribution is publicly verifiable via their ZK-Proof |
| Liveness | Any participant can verify the final CRS is correctly computed |
| Auditability | All proofs and contributions are published — ceremony is reproducible |

### Implementation (Rust/bellman)

```rust
use bellman::groth16::generate_random_parameters;
use ark_bls12_381::{Bls12_381, Fr};

pub fn contribute_to_ceremony(
    previous_params: &MpcParams,
    rng: &mut impl RngCore,
) -> (MpcParams, ContributionProof) {
    // s_i: secret scalar, generated in secure context
    let s_i = Fr::rand(rng);

    // Apply contribution: multiply all elements by s_i
    let new_params = previous_params.contribute(s_i);

    // Generate proof of knowledge of s_i
    let proof = generate_contribution_proof(s_i, previous_params, &new_params);

    // s_i must be dropped here — zeroed from memory
    drop(s_i); // Rust's Drop ensures zeroing

    (new_params, proof)
}
```

---

## Rationale

**Why MPC over single-party trusted setup:**  
A single trusted party is a single point of failure. If compromised (insider threat, coercion, memory forensics), τ is known and all future proofs can be forged. MPC distributes the trust: even if n-1 participants are all compromised, the ceremony is secure.

**Why Secure Enclave for s_i generation:**  
Generating s_i in the Secure Enclave (Apple Silicon) or TPM means the scalar never appears in main memory — prevents cold boot attacks, memory dumps, and side-channel recovery.

---

## Consequences

**Positive:** No single point of trust — ceremony requires full n-1 collusion to break. Each contribution is independently verifiable. CRS is a public good — shared across the entire constellation.

**Negative / Mitigations:**
- **Setup is one-time but takes ~10s compute:** Done offline before deployment → not a runtime concern
- **Proving Key is ~100MB:** Stored on SSD, loaded to RAM only during proof generation → negligible I/O cost
